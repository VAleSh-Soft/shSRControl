Практически все методы идентичны для обоих объектов - и WiFi-реле, и WiFi-выключателя. Поэтому описываться они будут в общем. В случае каких-то отличий будут делаться соответствующие примечания.

***Примечание:** для методов, применимых только к одному какому-то модулю будет указываться имя класс (например `void shSwitchControl::init(uint8_t _switch_count)`), для методов, одинаковых для обоих модулей имя класса указываться не будет (например `bool startDevice(WiFiUDP *_udp)`)*

### Свойства локальных и удаленных реле

#### Свойства реле - shRelayData

```
struct shRelayData
{
  String relayName;          
  uint8_t relayPin;          
  uint8_t relayControlLevel; 
  bool relayLastState;
  srButton *relayButton;
  String relayDescription;
};
```
Здесь:
- `relayName` - имя реле (идентификатор), по которому к нему будет обращаться выключатель; имена реле не должны повторяться в пределах одного модуля; в случае одинаковых имен будет срабатывать всегда то, индекс которого в массиве меньше;
- `relayPin` - пин, к которому подключено реле;
- `shRelayControlLevel` - управляющий уровень реле (LOW или HIGH)
- `relayLastState` - последнее состояние реле;
- `relayButton` - локальная кнопка, управляющая реле (располагается на самом модуле и предназначена для ручного управления реле); если локальная кнопка не нужна, свойству `relayButton` присваивается значение **nullptr**;
- `relayDescription` - описание реле, которое будет видно в Web-интерфейсе;

#### Свойства реле - shSwitchData

```
struct shSwitchData
{
  String relayName;
  bool relayFound;
  IPAddress relayAddress;
  shButton *relayButton;
  String relayDescription;
};
```
Здесь:
- `relayName` - имя ассоциированного с кнопкой удаленного реле; имена реле не должны повторяться в пределах одного модуля; в случае одинаковых имен команда на переключение всегда будет подаваться по адресу реле, индекс которого в массиве меньше;
- `relayFound` - найдено или нет ассоциированное удаленное реле в сети; свойству присваивается **false** после отправки запроса на переключение реле (или его поиска в сети) и присваивается **true** после получения отклика от него;
- `relayAddress` - сохраненный последний IP-адрес модуля реле; по этому адресу выключатель отправляет запрос на переключение реле;
- `relayButton` - локальная кнопка, управляющая удаленным реле с именем `relayName`; если локальная кнопка не нужна, свойству `relayButton` присваивается значение **nullptr**;
- `relayDescription` - описание ассоциированного удаленного реле;

### Инициализация и запуск модуля

создание объекта
```
shSwitchControl switch_control; // для модуля WiFi-выключателя
shRelayControl relay_control;   // для модуля WiFi-реле 
```

инициализация модуля
```
void shSwitchControl::init(uint8_t _switch_count);
void shRelayControl::init(uint8_t _relay_count);
```
в качестве аргумента указывается количество реле (удаленных или локальных), которые будут использоваться модулем.

заполнение списка реле
```
bool shSwitchControl::addRelay(const String &relay_name, 
                               srButton *relay_button = nullptr);
```
здесь:
- `relay_name` - имя удаленного реле, которое будет управляться модулем;
- `relay_button` - ссылка на объект класса `srButton`, который будет использоваться для локального управления удаленным реле; обычная кнопка без фиксации; если не указать кнопку, то управлять этим удаленным реле можно будет только через Web-интерфейс;

```
bool shRelayControl::addRelay(const String &relay_name,
                              uint8_t relay_pin,
                              uint8_t control_level,
                              srButton *relay_button = nullptr,
                              const String &relay_description = "");
```
здесь:
- `relay_name` - имя локального реле, которое будет управляться модулем;
- `relay_pin` - номер пина, на котором будет подключено локальное реле;
- `control_level` - уровень управления локальным реле (`HIGH` или `LOW`);
- `relay_button` - ссылка на объект класса `srButton`, который будет использоваться для локального управления этим реле; обычная кнопка без фиксации; если не указать кнопку, то управлять этим локальным реле можно будет только через Web-интерфейс;
- `relay_description` - описание локального реле; можно не задавать здесь, это можно будет сделать через Web-интерфейс;

Реле добавляются в список последовательно и имеют соответствующие порядку их добавления индексы в списке (**0 .. relayCount - 1**).

подключение Web-интерфейса

```
void attachWebInterface(shWebServer *_server,
                          FS *_file_system,
                          const String &_relay_config_page = "/relay_config",
                          const String &_tasks_config_page = "",
                          const String &_wifi_config_page = "");
```
здесь:
- `_server` - ссылка на экземпляр Web-сервера, с которым будет работать модуль;
- `_file_system` - ссылка на экземпляр файловой системы модуля для сохранения файлов с настройками;
- `_relay_config_page` - адрес, по которому будет вызываться Web-страница конфигурации реле; если задать здесь пустую строку, то возможности настраивать реле через Web-интерфейс не будет;
- `_tasks_config_page` - адрес, по которому будет вызываться Web-страница планировщика заданий и настройки параметров времени модуля; если задать здесь пустую строку, то планировщик использоваться не будет;
- `_wifi_config_page` - адрес, по которому будет вызываться Web-страница настройки WiFi; необязательна к использования;

запуск модуля

***Важно!!!** вызывать следующие методы можно только после установки WiFi-соединения*

```
bool startDevice(WiFiUDP *_udp, uint16_t _udp_port);
bool startDevice(WiFiUDP *_udp);
```
здесь:
- `_udp` - ссылка на экземпляр **WiFiUDP**, который будет использоваться для работы модуля;
- `_udp_port` - порт для отправки/приема udp-пакетов; должен быть одинаковым для всех связанных модулей;

***Примечание:** - второй вариант предполагает, что UDP-порт уже задан заранее, в противном случае будет использован порт по умолчанию **54321***

***Примечание:** если вы предполагаете использовать только модули WiFi-реле и управлять ими исключительно через Web-интерфейс, то метод `startDevice()` можно не вызывать*

обработка событий модуля loop()

```
void tick();
```
должен запускаться как можно чаще
```
void loop()
{
  switch_control.tick();
}
```

### Конфигурация модуля

#### Работа с сетью

установить номер UDP-порта, с которым будет работать модуль
```
void setUdpPort(uint16_t _udp_port);
```
здесь:
- `_udp_port` - номер UDP-порта;
***ВАЖНО!!!** - после изменения номера порта модуль нужно обязательно перезагрузить, чтобы изменения вступили в силу; поэтому применять этот метод нужно до вызова метода `startDevice()`*

получение текущего номера UDP-порта
```
uint16_t getUdpPort();
```

#### Вывод отладочной информации

включение/отключение вывода отладочной информации о работе модуля
```
void setLogOnState(bool _on, Print *_serial = &Serial);
```
здесь:
- `_on` - новое состояние опции;
- `_serial` - интерфейс для вывода сообщений; это может быть любой интерфейс, наследующий класс `Print` - будь то `Serial`, `File` или какой-нибудь экран;

получение текущего состояния опции
```
bool getLogOnState();
```

#### Озвучивание событий

##### Ошибки в отправке пакетов

оповещение об ошибке отправки пакета в связи с недоступностью удаленного реле; доступно только для модуля WiFi-выключателя
```
void shSwitchControl::setErrorBuzzerState(bool _state, int8_t _pin = -1);
```
здесь:
- `_state` - новое состояние опции;
- `_pin` - пин, к которому подключен буззер; если номер пина будет меньше нуля, то опция будет отключена без вариантов;
- 
***Примечание:** в случае, если модуль будет пытаться отправить пакет недоступному удаленному реле, будет выдаваться короткий двойной пик, в случае, если в этот момент не будет WiFi-подключения, будет выдаваться короткий тройной пик*

***Примечание:** при включении этой опции будет так же включено озвучивание клика локальных кнопок*

получение текущего состояния опции
```
bool shSwitchControl::getErrorBuzzerState();
```

void shRelayControl::setButtonBuzzerState(bool _state, int8_t _pin = -1);

здесь:
- `_state` - новое состояние опции;
- `_pin` - пин, к которому подключен буззер; если номер пина будет меньше нуля, то опция будет отключена без вариантов;

настройка звукового сигнала для нажатия локальных кнопок

void setBtnBeepData(uint16_t _freq, uint32_t _dur);

здесь:
- `_freq` - частота сигнала в Гц;
- `_dur` - длительность сигнала в мс;

#### Сохранение конфигурации

установка имени файла конфигурации
```
void shSwitchControl::setFileName(const String &_name, srModuleType _mdl = mtSwitch);
void shRelayControl::setFileName(const String &_name, srModuleType _mdl = mtRelay);
```
здесь:
- `_name` - новое имя файла;

  - `mtNtp` - для модуля NTP;

получение текущего имени файла конфигурации
```
String shSwitchControl::getFileName(srModuleType _mdl = mtSwitch);
String shRelayControl::getFileName(srModuleType _mdl = mtRelay);
```
здесь:
- `_mdl` - тип модуля;

загрузка конфигурации; при загрузке параметры будут подгружены в соответствующие поля настроек
```
bool shSwitchControl::loadConfig(srModuleType _mdl = mtSwitch);
bool shRelayControl::loadConfig(srModuleType _mdl = mtRelay);
```
здесь:
- `_mdl` - тип модуля; может иметь значения:
  - `mtSwitch` - для модуля WiFi-реле;
  - `mtRelay` - для модуля WiFi-выключателя;
  - `mtTasks` - для модуля планировщика задач;
  - `mtNtp` - для модуля NTP;

сохранение конфигурации; при сохранении параметры будут сохранены с соответствующих им файлах
```
bool shSwitchControl::saveConfige(srModuleType _mdl = mtSwitch);
bool shRelayControl::saveConfige(srModuleType _mdl = mtRelay);
```
здесь:
- `_mdl` - тип модуля;

### Работа с локальными и удаленными реле

поиск связанных реле в сети; этот метод отправляет широковещательный запрос по сети с просьбой откликнуться всем доступным модулям; при ответе IP-адреса удаленных реле сохраняются в файле конфигурации, и вся дальнейшая работа с этими реле идет уже по конкретным адресам; метод доступен только для модуля WiFi-выключателя;
```
void shSwitchControl::findRelays()
```

переключение состояния реле; можно использовать как имя реле, так и индекс этого реле в массиве
```
void switchRelay(int8_t index);
void switchRelay(String _name);
```
здесь:
- `index` - индекс реле в массиве;
- `_name` - имя реле; 

установка состояния реле; здесь так же можно использовать как имя реле, так и индекс этого реле в массиве
```
void setRelayState(uint8_t index, bool state);
void setRelayState(String _name, bool state);
```
здесь:
- `index` - индекс реле в массиве;
- `_name` - имя реле; 
- `state` - новое состояние реле;

получение текущего состояния реле; доступно только для модуля WiFi-реле
```
String shRelayControl::getRelayState(int8_t index);
String shRelayControl::getRelayState(String _name);
```
здесь:
- `index` - индекс реле в массиве;
- `_name` - имя реле; 

***Примечание:** методы возвращают строковое значение: "on" или "off"*

установка состояния всех удаленных реле сразу
```
void shSwitchControl::setStateForAll(bool state, bool _self = true);
```
здесь:
- `state` - новое состояние всех удаленных реле;
- `_self` - если true - команда на изменения состояния посылается только для реле, ассоциированных с выключателем; иначе команда посылается для всех реле, доступных в сети;

установка состояния всех локальных реле сразу
```
void shRelayControl::setStateForAll(bool state);
```
здесь:
- `state` - новое состояние всех локальных реле;

### Работа со временем

установка времени модуля
```
void setTimeToModule(time_t _now);
```
здесь:
- `_now` - время в формате unix time;

получение текущего времени модуля в формате unix time
```
time_t getTimeFromModule();
```

***Примечание:** время модуля не учитывает смещение по часовому поясу; смещение по часовому поясу устанавливается отдельно*

установка смещения времени по часовому поясу; по умолчанию установлено смещение +180 минут (+3 часа, Московское время)
```
void setTimeZoneOffset(time_t _tz);
```
здесь:
- `_tz` - смещение в минутах;

получение текущего смещения времени по часовому поясу в минутах
```
time_t getTimeZoneOffset();
```

установка параметров NTP
```
  void setNtpData(bool _enabled,
                  time_t _tz = 180,
                  String _ntp_srv1 = "",
                  String _ntp_srv2 = "",
                  String _ntp_srv3 = "");
```
здесь:
- `_enabled` - включение/отключение синхронизации времени с NTP-серверами;
- `_tz` - смещение часового пояса в минутах;
- `_ntp_srv1` - первый NTP-сервер;
- `_ntp_srv2` - второй NTP-сервер;
- `_ntp_srv3` - третий NTP-сервер;

***Примечание:** список серверов по умолчанию - ru.pool.ntp.org, pool.ntp.org, time.google.com*

получение текущего состояния синхронизации времени с NTP-серверами - используется или не используется
```
bool getNtpStatus();
```

получение текущих NTP серверов
```
String getNtpServer1();
String getNtpServer2();
String getNtpServer3();
```

### Работа с планировщиком задач

#### Описание параметров задачи - shSchedulerData

каждая задача планировщика имеет следующие поля
- `bool task_status` - статус задачи (активна / отключена);
- `int32_t time_for_task` - время срабатывания задачи, минут с начала суток;
- `uint8_t relay_index` - индекс реле которым управляет задача; имеется в виду индекс в массиве реле;
- `bool action_for_relay` - действие с реле (включить/выключить);
- `shTaskRepeat task_repeat` - периодичность выполнения задачи;

Пример использования
```
// задача будет включать реле с индексом 0 в 22:42 в понедельник и среду
shSchedulerData task{.task_status = true,
                     .time_for_task = 22 * 60 + 42,
                     .relay_index = 0,
                     .action_for_relay = true,
                     .task_repeat = (shTaskRepeat)(TR_MON_DAY | TR_WED_DAY)};
switch_control.addTaskToList(task);
```

***Примечание:** задачи можно сравнивать между собой; одинаковыми будут считаться задачи, у которых совпадают все поля, кроме `.task_status`*

#### Флаги периодичности выполнения задачи - shTaskRepeat

- TR_ONCE = 0x00,    // однократное срабатывание; 0b00000000
- TR_MON_DAY = 0x01, // по понедельникам;         0b00000001
- TR_TUE_DAY = 0x02, // по вторникам;             0b00000010
- TR_WED_DAY = 0x04, // по средам;                0b00000100
- TR_THU_DAY = 0x08, // по четвергам;             0b00001000
- TR_FRI_DAY = 0x10, // по пятницам;              0b00010000
- TR_SAT_DAY = 0x20, // по субботам;              0b00100000
- TR_SUN_DAY = 0x40, // по воскресеньям;          0b01000000
- TR_DAILY = 0x80    // ежедневное срабатывание;  0b10000000

поле задачи `.task_repeat` может иметь значение `TR_ONCE`, `TR_DAILY` или сочетание флагов дней недели; пример использования см. выше;

***Примечание:** если задать все семь дней недели, то при добавлении задачи ей будет выставлено значение `.task_repeat = TR_DAILY` - ежедневное выполнение*

#### Методы для работы с планировщиком

добавление новой задачи
```
bool addTaskToList(shSchedulerData &_task);
```
здесь:
- `_task` - структура, описывающая задачу;

***Примечание:** при добавлении задачи проверяется наличие дубликата в списке; в случае, если задача с такими параметрами существует, то новая задача добавляться не будет, вместо этого найденной задаче будет присвоено значение `.task_status` добавляемой задачи; метод при этом вернет **true***

поиск задачи в списке планировщика по заданным параметрам; возвращает индекс задачи в списке планировщика или -1, если задача не найдена
```
uint8_t findTask(shSchedulerData &_task);
```
здесь:
- `_task` - структура, описывающая искомую задачу;
```
int8_t findTask(int32_t _time_for_task,
                uint8_t _relay_index,
                bool _action_for_relay,
                shTaskRepeat _task_repeat);
```
здесь:
- `_time_for_task` - время в секундах, когда должна выполняться задача;
- `_relay_index` - индекс целевого реле в массиве;
- `_action_for_relay` - действие, которое должно выполняться для этого реле;
- `_task_repeat` - периодичность выполнения задачи;

удаление задачи из списка
```
bool delTaskInList(uint8_t _idx);
```
здесь:
- `_idx` - индекс задачи в списке планировщика;

установка статуса задачи - активна / выключена
```
void setTaskStatus(uint8_t _idx, bool _state);
```
здесь:
- `_idx` - индекс задачи в списке планировщика;
- `_state` - новый статус задачи;

изменение данных существующей задачи
```
bool setTaskData(uint8_t _idx, shSchedulerData &_task);
```
здесь:
- `_idx` - индекс задачи в списке планировщика;
- `_task` - новые данные задачи;

получение количества задач в планировщике
```
uint8_t getTaskCount(bool is_active = false);
```
здесь:
- `is_active` - считать только активные задачи;

### Работа с кнопками

#### События и состояние кнопки

Для работы с тактовыми кнопками модулей используется внутренний модуль **srButton.h**, который является адаптированной для использования здесь копией библиотеки [shButton](https://github.com/VAleSh-Soft/shButton). Все методы и возвращаемые значения аналогичны таковым библиотеки **shButton**.

// состояние кнопки
- `BTN_RELEASED` (0) - кнопка отпущена
- `BTN_PRESSED` (1) - кнопка нажата, но время удержания не вышло

// события кнопки
- `BTN_UP` (2) - кнопка только что отпущена
- `BTN_DOWN` (3) - кнопка только что нажата
- `BTN_DBLCLICK` (4) - двойной клик - второе нажатие до истечения интервала двойного клика; если непрерывно быстро щелкать кнопкой, будут поочередно выдаваться события BTN_DOWN и BTN_DBLCLICK

// виртуальные события кнопки
- `BTN_ONECLICK` (5) - одиночный клик, следует через некоторый интервал после нажатия кнопки, если за это время не последовал двойной клик или длительное удержание кнопки нажатой; по умолчанию событие отключено
- `BTN_LONGCLICK` (6) - событие, соответствующее удержанию кнопки дольше времени удержания; может быть быть непрерывным (по умолчанию), однократным или следовать через определенные интервалы

// режимы отработки удержания кнопки

- `LCM_CONTINUED` (0) - непрерывное событие BTN_LONGCLICK, генерируется постоянно, пока кнопка удерживается нажатой, если интервал удержания превышен;
- `LCM_ONLYONCE` (1) - однократное событие BTN_LONGCLICK, генерируется только один раз по истечении интервала удержания кнопки, после чего будет постоянно выдаваться BTN_PRESSED до тех пор, пока кнопка будет удерживаться нажатой; значение по умолчанию
- `LCM_CLICKSERIES` (2) - по истечении интервала удержания кнопки событие BTN_LONGCLICK генерируется постоянно через равные интервалы времени, в промежутках выдается BTN_PRESSED;

#### Объявление кнопок

Для работы с модулями используются кнопки с нормально разомкнутыми контактами, подключаемые к пинам, имеющим внутреннюю подтяжку к **VCC**, замыкаться кнопки должны на GND; 

объявление кнопки выглядит следующим образом:
```
srButton btn_1(16);
```
где **16** - пин, к которому подключена кнопка;

***Примечание:** для кнопки используется программное подавление дребезга,  интервал подавления дребезга контактов по умолчанию составляет 50мс; если вам необходимо изменить интервал подавления дребезга (увеличить, или уменьшить - например, вы используете аппаратное подавление дребезга или вообще сенсорные кнопки), то новый интервал антидребезга (в милисекундах) можно добавить вторым параметром конструктора - `srButton(16, 80)`*

***Важно!!!** для кнопок доступны все методы класса `srButton`, однако гораздо удобнее и безопаснее использовать приведенные ниже методы*

#### Методы для работы с кнопками

***Примечание:** т.к. кнопки привязаны к конкретным реле, то для их определения указывается индекс реле в массиве (см. описание метода `addRelay()`)*

получение состояния кнопки
```
uint8_t getButtonState(uint8_t _idx);
```
здесь:
- `_idx` - индекс в массиве реле, к которому привязана кнопка;

пример использования - определение клика кнопкой, привязанной к реле с индексом 0:
```
if (switch_control.getButtonState(0))
{
    // кнопка нажата
}
```

***Примечание:** если к конкретному реле кнопка не привязана, все методы возвращают результат BTN_RELEASED (0)*

определение состояния кнопки; возвращает true, если по результатам последнего опроса кнопка нажата
```
bool isButtonClosed(uint8_t _idx);
```
здесь:
- `_idx` - индекс в массиве реле, к которому привязана кнопка;

определение одновременного нажатия двух кнопок; возвращает true, если в момент возникновения события btn_state кнопки с индексом _idx кнопка с индексом _but_2 уже нажата; если метод вернул true, состояние обеих кнопок сбрасывается
```
bool isSecondButtonPressed(uint8_t _idx, uint8_t _but_2, uint8_t btn_state = BTN_DOWN);
```
здесь:
- `_idx` - индекс в массиве реле, к которому привязана кнопка;
- `_but_2` - индекс в массиве реле, к которому привязана вторая кнопка;
- `btn_state` - состояние, которое отслеживается методом; по умолчанию обычный

принудительный сброс состояния кнопки; может понадобиться, если по каким-то причинам нужно, например, исключить возникновение событий `BTN_ONECLICK` и `BTN_DBLCLICK`
```
void resetButtonState(uint8_t _idx);
```
здесь:
- `_idx` - индекс в массиве реле, к которому привязана кнопка;

установка режима обработки удержания кнопки нажатой; возможные варианты 
- LCM_CONTINUED; 
- LCM_ONLYONCE; режим по умолчанию
- LCM_CLICKSERIES;
```
void setButtonLongClickMode(uint8_t _idx, uint8_t longclickmode);
```
здесь:
- `_idx` - индекс в массиве реле, к которому привязана кнопка;
- `longclickmode` - режим обработки удержания кнопки нажатой;

установка интервала удержания кнопки (значение по умолчанию 1000 мс)
```
void setButtonTimeoutOfLongClick(uint8_t _idx, uint16_t new_timeout);
```
здесь:
- `_idx` - индекс в массиве реле, к которому привязана кнопка;
- `new_timeout` - новый интервал удержания кнопки;
